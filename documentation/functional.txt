**1.0 Purpose**
To design and implement a data processing pipeline to ingest, transform, and export ABC historical sales order data for demand forecasting.

**2.0 Scope**
2.1: In scope for this document is:
* Ingestion of ABC historical sales order data and regional mapping data from flat files.
* Transformation of ingested data into a suitable format for demand forecasting.
* Export of transformed data to a CSV file.

2.2: Out of scope for this document is:
* Creation/execution of test scripts.

### 7.2 Data Ingestion:

1. Ingest historical sales order data and regional mapping data from flat files into Bronze layer.
2. Store ingested data in Bronze tables: `b_um_xyz.ABC_onetime_history_sales_orders` and `b_um_xyz.ABC_onetime_history_sales_org_plant_xref`.

### 7.3 Data Transformation:

1. Transform ingested data by joining historical sales order data with regional mapping data on product and LOC.
2. Apply mapping rules to populate key fields: Sales Organization, Region, Sales Office, Plant, Planning Partner, Demand Quantity, and Return Quantity.
3. Store transformed data in Silver table: `s_xyz.sales_orders_demand_fcst_ABC_onetime_history`.

**Flow Diagram:**

Historical Sales Order Data → Bronze Layer → Silver Layer → Gold Layer
Regional Mapping Data → Bronze Layer → Silver Layer

**Execution Steps:**

1. Ingest data into Bronze layer.
2. Transform data in Silver layer.
3. Create Gold view: `g_external.v_sales_orders_demand_fcst_ABC_onetime_history`.

**Schema TableName Description**

| Schema | TableName | Description |
| --- | --- | --- |
| b_um_xyz | ABC_onetime_history_sales_orders | Bronze table for historical sales order data |
| b_um_xyz | ABC_onetime_history_sales_org_plant_xref | Bronze table for regional mapping data |
| s_xyz | sales_orders_demand_fcst_ABC_onetime_history | Silver table for transformed data |
| g_external | v_sales_orders_demand_fcst_ABC_onetime_history | Gold view for demand forecasting |

### 7.4 Data Export:

1. Export transformed data from Gold view to a CSV file.
2. Store CSV file in ADLS path: `abfss://mft@{storage_account}.dfs.core.windows.net/outbound/supply-chain-management/scm-demand-fcst/5Y_ABC_onetime_SCM_demand_history.csv`.

### 7.5 Data Processing
Databricks provides a unified platform for scalable and efficient data processing, powered by Apache Spark as its core engine. Here, Databricks notebooks are orchestrated using Databricks Workflows.

### 7.6 Data Optimization
Regular optimization scripts are scheduled in Databricks to maintain table performance and ensure efficient query execution.

### 7.7 Data Security
Data access in Databricks is restricted to authorized user groups, such as Data Engineers and Data Analysts, based on their roles and responsibilities.

### 7.8 Data Archiving
Data is archived for 15 days on Azure Data Lake Storage (ADLS).
