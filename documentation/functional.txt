## 1.0 Purpose
To develop a data transformation process that maps data from source tables to the silver table "s_onc.sales_ord_his" following specific business rules and data mapping requirements.

## 2.0 Scope
### 2.1: In scope for this document is:
Development of ETL processes to transform data from b_onc.Sales and b_onc.sales_org tables into the s_onc.sales_ord_his silver table according to specified mapping rules.

### 2.2: Out of scope for this document is:
- Any modifications to source data structures
- Creation of downstream gold layer tables
- Integration with external systems beyond specified source tables

## 7.0 Data Product Design

### 7.1 Data Sources
| Source | Description | Columns | ADLS Path |
|--------|-------------|---------|-----------|
| b_onc.Sales | Sales transaction data | DMDUNIT, DMDGROUP, LOC, STARDATE, DUR, TYPE, EVENT, QTY, HISTSTREAM | /bronze/onc/sales |
| b_onc.sales_org | Sales organization data | PRODUCT, LOC, Region, Country, Channel, Sales Org, Plant/DC | /bronze/onc/sales_org |

#### 7.1.1 Input File layout:
| FieldName | Description | Mandatory | Comments |
|-----------|-------------|-----------|----------|
| DMDUNIT | Demand Unit | Yes | Maps to APM Model Number |
| DMDGROUP | Demand Group | Yes | Used for Planning Partner determination |
| LOC | Location | Yes | Used for multiple field mappings |
| STARDATE | Start Date | Yes | Used for Cal Month calculation |
| QTY | Quantity | Yes | Used for demand quantity calculations |
| HISTSTREAM | History Stream | Yes | Determines type of quantity (sales or returns) |
| PRODUCT | Product ID | No | From sales_org table |
| Region | Region | No | From sales_org table |
| Country | Country | No | From sales_org table |
| Channel | Channel | No | From sales_org table |
| Sales Org | Sales Organization | No | From sales_org table |
| Plant/DC | Plant/Distribution Center | No | From sales_org table |

### 7.2 Data Ingestion:
| Step | Details |
|------|---------|
| 1 | Extract data from b_onc.Sales table |
| 2 | Extract data from b_onc.sales_org table |
| 3 | Load data into Databricks processing environment |

### 7.3 Data Transformation:

```
[Source Tables] -> [Join & Apply Mapping Rules] -> [Apply Default Values] -> [Silver Table]
```

#### Execution Steps:
1. Join b_onc.Sales and b_onc.sales_org tables on LOC field
2. Apply mapping rules for each target field according to specifications
3. Apply conditional logic for Planning Partner field based on DMDGROUP values
4. Set default values for fields without source mappings
5. Calculate Cal Month from STARTDATE
6. Separate quantities based on HISTSTREAM value
7. Load transformed data into s_onc.sales_ord_his

#### Tables:
| Schema | TableName | Description |
|--------|-----------|-------------|
| b_onc | Sales | Bronze layer sales transaction data |
| b_onc | sales_org | Bronze layer sales organization data |
| s_onc | sales_ord_his | Silver layer sales order history data |

### 7.4 Data Export
| Step | Details |
|------|---------|
| 1 | Write transformed data to s_onc.sales_ord_his table |
| 2 | Validate data integrity and completeness |

## 9.0 Appendices / Attachments

### Functional Requirements

* **FR-001:** The system shall extract data from source tables b_onc.Sales and b_onc.sales_org.

* **FR-002:** The system shall populate APO Planning Version with a hard-coded value of "001".

* **FR-003:** The system shall map DMDUNIT from b_onc.Sales to APM Model Number, using the APO Product mapping in SCM.

* **FR-004:** The system shall map DMDUNIT from b_onc.Sales to Product Planner Code, using the Product Planner code mapping in SCM.

* **FR-005:** The system shall derive Country from LOC in b_onc.Sales by trimming to 2 characters.

* **FR-006:** The system shall determine Sales Office by combining LOC with Region Code via cross-reference mapping.

* **FR-007:** The system shall map LOC to BD Salesorg via cross-reference to populate Sales Organization.

* **FR-008:** The system shall map LOC to BD Location via cross-reference to populate PLANT.

* **FR-009:** The system shall implement the following Planning Partner mapping logic:
  * If DMDGROUP = SALES, then Planning partner = R
  * If DMDGROUP = SAMPLES, then Planning partner = N
  * If DMDGROUP = CONSIGN, then Planning partner = C

* **FR-010:** The system shall set default values for the following fields:
  * Distribution Channel: "10"
  * Customer Group: "500"
  * Ship-To Party: "NONE"
  * Sold-to Party: "NONE"
  * WW Business: "None"
  * Strategy Center: "None"
  * Product Line: "None"
  * Planning Set: "None"
  * Product Subset: "None"
  * Item Category: "None"
  * Sales Document Type: "None"
  * Base Unit of Measure: "EA"
  * Source System: "JDAAPM"

* **FR-011:** The system shall generate Snapshot ID using the system date/time.

* **FR-012:** The system shall map STARTDATE to Cal Month format.

* **FR-013:** The system shall populate Demand Quantity - MTS with QTY from b_onc.Sales where HISTSTREAM = "Actual Sales Qty".

* **FR-014:** The system shall populate Total Demand with the same value as Demand Quantity.

* **FR-015:** The system shall populate Returns Qty - MTS with QTY from b_onc.Sales where HISTSTREAM = "Return Qty".

* **FR-016:** The system shall implement conditional logic for field mappings based on whether product from sales_org is null/blank or not.

* **FR-017:** The system shall write the transformed data to the silver table s_onc.sales_ord_his.
