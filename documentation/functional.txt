**1.0 Purpose**
To design and implement an inbound interface for SCM Demand History data using Azure Databricks.

**2.0 Scope**
2.1: In scope for this document is:
* Ingestion of APM historical sales order data and regional mapping data into Azure Databricks.
* Transformation and processing of ingested data to generate demand history data.
* Export of processed data to a CSV file.

2.2: Out of scope for this document is:
* Creation and execution of test scripts.

**3.0 Definitions / Acronyms**

| Term / Abbreviation | Definition |
| --- | --- |
| APM | Advanced Planning Module |
| SCM | Supply Chain Management |
| ADLS | Azure Data Lake Storage |

**4.0 Roles and Responsibilities**

* Data Engineers: Responsible for designing and implementing the data ingestion and processing pipeline.
* Data Analysts: Responsible for consuming the processed data for demand forecasting and analysis.

**5.0 References**
Implement a PySpark job to ingest, transform, and export SCM Demand History data.

**5.1 Data Product Identification**
SCM Demand History Data

**5.2 Data Product Specification**
The data product is designed to provide historical sales order data and regional mapping data for demand forecasting and analysis.

### 7.2 Data Ingestion:

1. Ingest historical sales order data and regional mapping data from JDA-APM into Azure Databricks using PySpark.
2. Load the ingested data into Bronze tables.

### 7.3 Data Transformation:

1. Transform the ingested data by joining the historical sales order data with regional mapping data on product and location.
2. Apply the mapping rules to generate the required fields (e.g., Sales Organization, Region, Sales Office, Plant, Planning Partner).
3. Load the transformed data into Silver tables.

**Flow Diagram:**

Historical Sales Order Data → Bronze Table → Silver Table
Regional Mapping Data → Bronze Table → Silver Table
Silver Table → Gold View

**Step-by-Step Execution:**

1. Ingest historical sales order data and regional mapping data into Bronze tables.
2. Transform the ingested data by joining the historical sales order data with regional mapping data.
3. Apply the mapping rules to generate the required fields.
4. Load the transformed data into Silver tables.
5. Create a Gold view from the Silver table.

**Schema TableName Description**

| Schema | TableName | Description |
| --- | --- | --- |
| b_um_isc | apm_onetime_history_sales_orders | Bronze table for historical sales order data |
| b_um_isc | apm_onetime_history_sales_org_plant_xref | Bronze table for regional mapping data |
| s_isc | sales_orders_demand_fcst_apm_onetime_history | Silver table for transformed data |
| g_external | v_sales_orders_demand_fcst_apm_onetime_history | Gold view for demand history data |

### 7.4 Data Export

1. Export the Gold view data to a CSV file.
2. Store the CSV file in the specified ADLS path.

**Step Details:**

1. Create a CSV file from the Gold view data.
2. Store the CSV file in the ADLS path: abfss://mft@{storage_account}.dfs.core.windows.net/outbound/supply-chain-management/scm-demand-fcst/5Y_APM_onetime_SCM_demand_history.csv

### 7.5 Data Processing
Databricks provides a unified platform for scalable and efficient data processing, powered by Apache Spark as its core engine. Here, Databricks notebooks are orchestrated using Databricks Workflows.

### 7.6 Data Optimization
Regular optimization scripts are scheduled in Databricks to maintain table performance and ensure efficient query execution.

### 7.7 Data Security
Data access in Databricks is restricted to authorized user groups, such as Data Engineers and Data Analysts, based on their roles and responsibilities.

### 7.8 Data Archiving
Data is archived for 15 days on Azure Data Lake Storage (ADLS).
