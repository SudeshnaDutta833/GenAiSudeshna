**1.0 Purpose**
To design and implement an inbound interface for Supply Chain Management (SCM) to ingest historical sales order data from JDA-APM into Azure Databricks.

**2.0 Scope**
2.1: In scope for this document is the ingestion of historical sales order data from JDA-APM into Azure Databricks, data transformation, and export of the transformed data to a CSV file.
2.2: Out of scope for this document is the creation/execution of any test script.

**3.0 Definitions / Acronyms**

| Term / Abbreviation | Definition |
| --- | --- |
| JDA-APM | JDA Advanced Planning Module |
| SCM | Supply Chain Management |
| ADLS | Azure Data Lake Storage |

**4.0 Roles and Responsibilities**

* Data Engineer: Responsible for designing and implementing the data ingestion and transformation process.
* Data Analyst: Responsible for validating the transformed data.

**5.0 References**
Implement a PySpark job to ingest historical sales order data from JDA-APM into Azure Databricks, transform the data, and export it to a CSV file.

**5.1 Data Product Identification**
The data product is the historical sales order data from JDA-APM.

**5.2 Data Product Specification**
The data product specification includes the layout of the input files, data transformation rules, and the output CSV file format.

### 7.2 Data Ingestion:

1. Ingest the historical sales order data from JDA-APM into Azure Databricks using the provided ADLS path.
2. Ingest the regional, sales orgs & plant mapping data from JDA-APM into Azure Databricks using the provided ADLS path.

### 7.3 Data Transformation:

1. Create a bronze table for the historical sales order data.
2. Create a bronze table for the regional, sales orgs & plant mapping data.
3. Create a silver table by joining the bronze tables based on the product and LOC columns.
4. Apply the data transformation rules as specified in the input file.

**Data Transformation Flow Diagram:**

Not provided here, but it should be a diagram showing the data flow from bronze to silver to gold.

**Data Transformation Steps:**

1. Create a silver table `s_isc.sales_orders_demand_fcst_apm_onetime_history` by joining the bronze tables `b_um_isc.apm_onetime_history_sales_orders` and `b_um_isc.apm_onetime_history_sales_org_plant_xref` based on the product and LOC columns.
2. Apply the data transformation rules as specified in the input file.

**Schema TableName Description**

| Schema | TableName | Description |
| --- | --- | --- |
| b_um_isc | apm_onetime_history_sales_orders | Bronze table for historical sales order data |
| b_um_isc | apm_onetime_history_sales_org_plant_xref | Bronze table for regional, sales orgs & plant mapping data |
| s_isc | sales_orders_demand_fcst_apm_onetime_history | Silver table for transformed data |
| g_external | v_sales_orders_demand_fcst_apm_onetime_history | Gold view for transformed data |

### 7.4 Data Export

1. Create a gold view `g_external.v_sales_orders_demand_fcst_apm_onetime_history` from the silver table.
2. Export the gold view to a CSV file using the provided ADLS path.

**7.5 Data Optimization**
Regular optimization scripts are scheduled in Databricks to maintain table performance and ensure efficient query execution.

**7.6 Data Security**
Data access in Databricks is restricted to authorized user groups.

**7.7 Data Archiving**
Data is archived for 15 days on Azure Data Lake Storage (ADLS).
